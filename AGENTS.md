# AptiQu content authoring rules

## Scope and workflow
- Follow the approved topic `subtopics.json` as the authority for subtopic names, order, IDs, learner descriptions, and `script_scope`. Do not silently broaden a script beyond that scope; use the source book to resolve ambiguities and ask the user when scope cannot be resolved.
- Use the user's current three-checkpoint workflow for each topic: (1) identify all meaningful subtopics and save their approved names, descriptions, priorities, IDs, positions, and detailed `script_scope` values in `subtopics.json`; (2) create detailed scripts for every approved subtopic; (3) quality-check all generated scripts for encoding and notation issues, JSON validity, duplication, factual and mathematical accuracy, approved-scope alignment, graph reachability, valid transitions, and answer/reference consistency. Do not extract objective questions from the book or generate additional question banks as workflow steps. Complete all three checkpoints for the topic before stopping for the user's review; do not pause for intermediate approval unless a genuine ambiguity blocks safe, scope-correct work.
- Use the local source book and the existing completed AptiQu artifacts as references. Do not run local database setup/actions or connect to a VPS unless the user explicitly changes that restriction. Do not perform migrations unless asked.

## Script quality
- Teach with detailed, student-friendly explanations that build reasoning in a purposeful sequence. Preserve useful existing content; do not shorten merely for brevity or inflate with repetition. Explain why methods work, show steps and checks, and use examples that prepare learners for the approved scope.
- Keep coverage complete and source-grounded. Include useful interactive practice, accurate hints, explanations, and remedial paths. Avoid repeated examples or explanations unless the repetition has a deliberate teaching purpose.
- Perform a mathematical and pedagogical audit before calling any script complete. Verify every factual statement, worked example, answer, option, hint, feedback message, and recap. Check boundary cases explicitly (including exponent rules), and make sure all parts of the lesson teach the same rule.
- Structural validity is necessary but not sufficient: also verify approved-scope alignment, source fidelity, question correctness, consistency, graph reachability, transition targets, answer-option IDs, and successful JSON parsing.
- Preserve established schema, IDs, question counts, and unrelated material unless a correction requires a change. Document unavoidable changes and unresolved source or scope limitations.
- Assign each question's EASY, MEDIUM, or HARD label from its actual reasoning load; do not leave all questions at MEDIUM by default or force a target distribution.
- Keep examples and practice purposeful: avoid immediately reusing every worked example's exact values in its question when fresh values would better test transfer. Preserve an exact-value question when it is deliberate guided practice, and keep remedial practice connected to the skill being repaired.
- For integrated or capstone scripts, use fresh problems that genuinely combine at least two previously taught skills. Avoid copying earlier-subtopic questions verbatim; make the learner choose and sequence methods, then verify the result.
- Use precise notation when teaching exactness and approximation: distinguish terminating decimals from rounded displays, use equality only for exact equivalence, and use approximation signs when appropriate. Express rounded significant-figure answers unambiguously (for example, 12,486 to three significant figures as 1.25 × 10^4).
- Check notation consistency throughout the full script, including repeating-decimal period markers, worked text, prompts, hints, explanations, options, and remedial feedback. A notation error repeated in several nodes is still one content defect that must be corrected everywhere.

## Depth, worked teaching, and answer-position balance
- Do not compress lessons into short rule summaries to reduce file size or line count. The user's quality benchmark includes scripts around 2,000 lines when the topic calls for that depth; treat this as a signal to inspect for missing development, not a mechanical line quota. Each lesson must teach the approved scope thoroughly enough for its stated duration and audience.
- Develop concepts step by step and explain why a rule or shortcut works. Worked examples must show meaningful intermediate calculations, justify transformations, identify likely errors, and demonstrate a relevant check (estimation, substitution, sign, units, boundaries, or another suitable check).
- Remedial branches must diagnose and explain the misconception behind the wrong answer before the learner attempts a fresh, targeted retry. Generic “review and continue” feedback is insufficient when a specific misconception can be named.
- Write complete metadata descriptions; verify they are not truncated or unfinished and that duration claims match the teaching content.
- For scripts with eight multiple-choice nodes, distribute correct answers evenly: exactly two each in A, B, C, and D. Vary the ordering pattern between scripts. Keep displayed options, stored question options, and correct-answer IDs synchronized. For a different question count, balance positions as evenly as possible and check for patterns that reveal answers.
- In checkpoint 3, audit instructional depth as well as structure: inspect whether the lesson actually develops its scope, whether examples show intermediate reasoning and checks, whether remedial feedback teaches, whether descriptions are complete, and whether answer positions are balanced. A valid graph and valid JSON do not satisfy these standards by themselves.
