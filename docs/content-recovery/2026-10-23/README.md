# Saved-content recovery — 23 October 2026

The production admin API initially reported **0 questions**, **214 published scripts**, twelve missing Number System scripts, and three absent HCF/LCM subtopics. Recovery published 1,636 questions (1,300 Number System, 130 HCF/LCM, 206 Decimal Fractions), restored three HCF/LCM subtopics, and added fifteen scripts (twelve Number System and three HCF/LCM), bringing the published script count to 229. The final read-back found zero question mismatches, zero missing published scripts and zero script graph/reference mismatches. The final API audit is recorded in `production-verification.json`; successful mutations and their production IDs are recorded in `api-receipts.jsonl`.

## Causes

1. **Bulk-import backend defect.** `AdminQuestionsService.bulkImportImpl` adds a server-computed `fingerprint` to each candidate, then passes the candidate into the strict public `questionFields` schema, which does not admit that internal field. A valid corrected production bulk request returned HTTP 400; the same record succeeded through `POST /questions`. The local backend fix validates only public fields and then retains the computed fingerprint. It is built and regression-tested locally; **the backend change has not been deployed**.
2. **Incompatible bank format.** 120 unique extracted questions had five choices, including 22 keyed to E, while the API requires exactly A–D. The screenshot's Decimal Fractions row 27 is one of these. 788 unique questions had durations below the API's 30-second minimum. Legacy calculation labels WRITTEN, ALGEBRAIC and MIXED also do not match the API enum; the bulk code silently defaulted them to MENTAL.
3. **Stale question references.** The twelve Number System scripts referenced nonexistent zero-padded `ns-q-...` IDs. The actual bank uses unpadded `rs-q-...` IDs. Cross-subtopic review items are pinned inline rather than changing the bank hierarchy. One purported division question actually pointed to an unrelated rationality question; its reference now uses the existing quotient-and-remainder question `rs-q-964`.
4. **Invalid HCF/LCM graphs.** Three lessons could not be recovered at startup: missing completion markers/transition arrays, four ` transitions` keys with a leading space, and a loop back to an earlier section that made later sections unreachable. Their missing parent subtopics also prevented 39 bank questions from resolving.
5. **Completion normalization defect.** The final audit found that the normalizer could add a sequential edge to an explicit COMPLETION node when JSONB reordered dictionary keys. The boundary lesson was republished as version 2 with its completion placed last before import, avoiding an edge invented by the deployed normalizer. The stored published definitions now have correct empty terminal transitions. The local fix preserves explicit completion nodes regardless of key order, with a regression test. This code fix is also **not deployed**.
6. **Copied banks.** HCF/LCM's AI directory contains exact copies of Number System's five supplement chunks (920 repeated rows). Recovery imports each external question key once and preserves the questions' stated subtopic keys.

## Corrections

`corrections.json` records source edits. Every adapted five-choice question retains its original correct choice; one incorrect distractor is removed and answer letters/explanations are synchronized. No question IDs or unique question counts were removed. Durations below 30 seconds are now 30. WRITTEN and ALGEBRAIC map to PEN_AND_PAPER; MIXED maps to LIGHT_PEN_AND_PAPER.

The review repaired equivalent fraction distractors, incomplete OCR prompts/explanations, stale hints, impossible numerical conditions, ambiguous choices, and incorrect answers. Four supplementary prime-factor questions incorrectly treated 4 or 6 as primes; their counts, choices, hints and explanations now factor the bases first. HCF/LCM q122 was rewritten with explicit beep intervals and endpoint counting because the original pendulum wording did not support its keyed answer. HCF/LCM q056/q057 needed consistent numerical conditions; q059 needed an unambiguous distractor. These are deliberate mathematical corrections, not verbatim reproductions of the printed source.

The original supplementary source files identify their provenance as AptiQu Original Supplementary Questions but use MANUAL as their source label. Production recovery uses AI_GENERATED / AI_SYNTHETIC for those 920 questions and MANUAL / AI_EXTRACTED for the 716 extracted book questions. Book, edition, chapter, page, exam reference and explanation fields are preserved through the single-question API.

## Verification and reproducibility

- `node --test backend/src/security/tests/content-import.unit.cjs backend/src/security/tests/content-recovery.unit.cjs` — eleven inert tests, including the actual bulk service against every unique saved question, duplicate rejection, graph validity, question references, display consistency, equivalent fractions and composite-base factor counts.
- `npm run build` in `backend/` — TypeScript compilation succeeds.
- `python3 backend/scripts/audit-saved-question-math.py` — 288 independently recomputed arithmetic, factorial, prime-factor and modular questions; results in `math-verification.json`. This targeted audit is not a full editorial review of every saved question or a rewrite of the legacy short lessons.
- `backend/scripts/recover-saved-content.cjs` uses authenticated HTTP APIs exclusively. Modes: `subtopics`, `questions`, `repair-questions`, `scripts`, `verify`. It requires an existing short-lived admin token in `/private/tmp/aptiqu-import-token`; no credential is embedded or logged. The temporary token is removed after recovery.
- Question recovery is resumable: existing keys are checked before insertion; every successful creation records an ID. Writes are paced below the production request budget and respect Retry-After. `repair-questions` synchronizes reviewed edits made while the long import was running. `verify` compares every expected saved question field and validates published script graphs and pinned external-question snapshots.

No local database was started or changed. No SQL, VPS/SSH connection, migration or backend deployment was performed. No standalone question bank exists for Simplification (topic four), so its inline lesson questions were not turned into a new question bank.
